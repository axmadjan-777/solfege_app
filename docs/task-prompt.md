# Шаблоны задачи и отчёта

Помогает задать результат, границы и способ приёмки, затем передать доказательства.
Постоянный процесс работы описан в [AGENTS.md](../AGENTS.md), продуктовая очередь —
в [roadmap](product_roadmap.md). Шаблоны подходят и для приложения, и для документации.

## Запрос

```text
Выполни одну задачу в solfege_app по AGENTS.md.

Задача: <ссылка на карточку, ID из roadmap или конкретное описание>.
Результат для пользователя: <что станет работать или понятнее>.
Сценарий приёмки: <действия и ожидаемый результат>.
Область изменений: <модули / документы / инструменты разработки>.
Ограничения: <что не менять; нужны ли живые сервисы>.
Git: <локально либо разрешённые коммит / push / PR>.
```

Необязательно заполнять все поля дословно. Агент восстанавливает понятные границы
из запроса и уже согласованных решений; спрашивает только о существенном пробеле.
Для работы с уроками или практикой используется
[руководство по учебной программе](curriculum/README.md).

## Пример задачи на аудит

```text
Проверь APP-01 из roadmap только на чтение.
Объясни, почему пройденный урок может не открывать следующий.
Покажи соответствующие места в коде и опиши путь пользователя через основной экран.
Не меняй приложение, документы, ветки или PR.
```

## Отчёт

Заполни для карточки и PR либо для локального результата без них. Для короткой
правки достаточно относящихся к ней полей; в ответе оставь главное и ссылку.
Условия завершения определяет [AGENTS.md](../AGENTS.md#когда-задача-готова).

```text
Что изменено: <результат и затронутая область>.
Критерии задачи: <каждый критерий → доказательство или открытый пункт>.
Что проверено: <команда/сценарий, окружение, результат; для прогона — время>.
Ручной сценарий: <действия и результат либо почему не требуется>.
Ревью: <что просмотрено; открытые блокирующие замечания или их отсутствие>.
Версия: <полный SHA проверенного коммита; для локальных правок — базовый SHA и сохранённый diff/идентификатор артефакта>.
Результат: <ссылка на PR, документ или другой артефакт>.
Что осталось: <не проверено/заблокировано и причина; ограничения вне объёма>.
Статус карточки, если есть: <текущий статус и основание; следующий шаг, если нужен>.
```

## Пример исправления одной фичи

Учебный пример локального сохранения результата; это не отчёт о найденном баге
или выполненных проверках. Обозначения `<SHA-A>` и `<SHA-B>` заменяются реальными
коммитами при работе.

| Статус | Действие и наблюдаемый результат в примере |
|---|---|
| Очередь → В работе | Взято исправление: после завершения упражнения результат должен читаться при повторном открытии. Зафиксированы версия и шаги потери записи. |
| В работе | Проверка через публичное хранилище пишет результат, закрывает и открывает хранилище; падает на отсутствующей записи. После минимального исправления тот же сценарий проходит. |
| В работе → Проверка | На `<SHA-A>` проходят затронутая область и итоговый набор. В браузере результат виден после повторного открытия. В карточке есть вывод проверок и PR. |
| Проверка → В работе | На ревью подтверждено: отказ записи показывает ложный успех. Добавлен сценарий отказа, который падает по этой причине; исправлена обработка ошибки. |
| В работе → Проверка | На `<SHA-B>` проходят оба сценария и итоговый набор; сообщение об ошибке проверено вручную, замечание закрыто повторным ревью. Облачное сохранение отмечено «не проверено, вне объёма локальной задачи». |
| Проверка → Готово | Все критерии локальной задачи подтверждены для `<SHA-B>`; разрешённый PR слит. В карточке сохранены ссылка на результат, проверенный SHA и коммит слияния. |

Шаблоны не хранят список дефектов, архитектуру или копию учебных требований.
Их изменение не требует переписывать запрос и отчёт.
