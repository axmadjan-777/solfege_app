# Промпт одной задачи по теории и практике

Работай по [AGENTS.md](../../AGENTS.md). Этот документ помогает выполнить выбранную
задачу; он не запускает всю программу разработки. Состояние и очередь — в
[roadmap](../product_roadmap.md), устройство приложения — в [README](../../README.md).

Обновлять при изменении шаблона задачи, правил контента или критериев готовности.
Итерации I0–I25 сохранены в [архиве](MVP_IMPLEMENTATION_PLAN.md). Его инструкции
о ветках, push и непрерывном продолжении не действуют. Архив не подтверждает
готовность MVP.

## Запрос для запуска

```text
Выполни одну задачу в solfege_app по AGENTS.md.

Задача: <ID из roadmap или конкретное описание>.
Результат для пользователя: <что станет работать>.
Сценарий приёмки: <действия и ожидаемый результат>.
Область изменений: <модули / документы / харнесс>.
Ограничения: <что не менять; нужны ли живые сервисы>.
Git: <локальные изменения либо разрешённые коммит/push/draft PR>.

Сначала сверь код и воспроизведи проблему. Читай связанные файлы по импортам,
спецификацию — по нужным ID и заголовкам. Выполни задачу, обнови документацию,
прогони целевые проверки и tool/verify.sh, проверь diff. Перед разрешённым
коммитом pre-commit проверит staged-снимок независимо от рабочей копии.
Сообщи результат, доказательства и ограничения. Не переходи к другой задаче
roadmap без нового поручения.
```

Шаблон необязательно заполнять дословно: восстанавливай границы из запроса и
согласованных решений, не переспрашивай очевидное. «Продолжай» означает завершить
текущую задачу. Если она завершена, а следующая не выбрана, предложи конкретный
пункт, не начинай весь архив.

## Как читать учебные требования

Каталог загружается из `assets/curriculum/*.json`, модели и загрузчик находятся
в `lib/features/curriculum/`. В каталоге 114 уроков, из них 56 с `mvp_status: mvp`.
Наличие остальных записей не разрешает реализовывать их. Карта теории в текущем
`main` уже показывает карточки уровней 5–11; расхождение с исходной границей MVP
отмечено в roadmap.

В [spec.md](spec.md) ищи нужный заголовок или ID и читай ограниченный фрагмент:

```bash
rg -n '^## |^### PR-|^### L00-01\.' docs/curriculum/spec.md
```

| Изменение | Части спецификации |
|---|---|
| Звук и скрытие нот до ответа | 5 |
| Прогресс, повторение, пороги | 6 и 9 |
| Один тренажёр | Его карточка в 8, параметры в JSON |
| Один урок | Его карточка в 11, объект в JSON |
| Состав MVP | 10 |
| Методическое решение | 16; прежние допущения — раздел 7 архива |
| Схемы данных | 17–20 и `schemas/*.json` |
| Целостность | 27 и `test/curriculum/` |

Части 21–26 с полным дампом не загружай; выбирай нужный объект из файла:

```bash
jq '.practice_sets[] | select(.id=="PR-01")' assets/curriculum/exercises.json
jq '.lessons[] | select(.id=="L04-11")' assets/curriculum/lessons.json
jq '.config.mastery_rules, .config.review_policies' assets/curriculum/levels.json
```

## Источник и обновление контента

Канонический источник генератора — именованные JSON-блоки в `spec.md`.
`assets/curriculum/*.json` и `docs/curriculum/schemas/*.json` — извлечённые копии
для приложения и тестов. Не редактируй только одну копию.

Если задача разрешает изменение содержания или схемы:

1. Исправь соответствующий исходный JSON-блок в `spec.md` и связанную прозу.
2. Запусти `python3 tool/extract_curriculum.py`.
3. Проверь diff всех копий, затем `python3 tool/extract_curriculum.py --check`
   и тесты целостности.

Задача по UI или харнессу не требует изменения контента. При расхождении прозы
и JSON явно назови обе стороны: структуру/параметры бери из JSON, методическое
намерение — из карточки. Новое продуктовое противоречие, меняющее критерий
приёмки, согласуй; не скрывай его поправкой порога.

## Методические ограничения

- Пользовательские строки по-русски, идентификаторы кода по-английски.
  Используй существующие `title`, `feedback` и `SolfegeNotes`: си = B.
- Доступность определяется сохранённым прогрессом. Проверяй его передачу из
  оболочки, а не только экран с тестовым `isMastered`. Немедленный успех и
  отложенное `mastered` не взаимозаменяемы.
- Пороги, диапазоны MIDI, стадии, `mvp_status` и интервалы повторения бери из
  данных. Не ослабляй их ради теста. Прежние разрешённые исключения — в разделе
  3 архива; читай только относящиеся к задаче.
- Генератор, проверка ответа и правила прогресса отделены от Flutter UI.
  Используй существующие `ProgressStore`, `PracticeAudioPlayer`, часы и seed.
- Микрофон, новые уровни/стадии, облачная синхронизация и лицензируемые сэмплы
  требуют отдельной задачи. Локальный прогресс `main` не считать облачным
  или изолированным между аккаунтами.

## Приёмка и проверки

Выбирай проверки по реальному риску:

- Контент: модели, ссылки, графы, границы MVP (`test/curriculum/`).
- Правила: чистая логика с фиксированными временем и seed (`test/practice/`,
  `test/theory/`).
- Экран: ответ → обратная связь → запись результата, с фейковым звуком.
- Интеграция: фактическая точка входа → урок/тренажёр → сохранение → повторное
  открытие. Для доступа и смены аккаунта проверяй оболочку и хранилище.

Не требуй одинаковых новых тестов для ссылки и нового тренажёра. Не заменяй
приёмку наличием файлов или тестом экрана «Supabase не настроен». Полная команда —
`bash tool/verify.sh`; состав и ограничения описаны в README.

Живой сценарий проверяй, когда он входит в задачу и есть тестовый доступ.
Без доступа перечисли непроверенное. Не называй весь MVP готовым по одному CI.

## Критерий завершения

- Выполнен согласованный сценарий, подтверждены границы задачи.
- Проверки зелёные либо точно описан исходный блокер вне области; при блокере
  нет статуса «принято».
- Документация соответствует изменению; предположения названы явно.
- Просмотрены diff и состав файлов; нет секретов и случайных правок зависимостей.
- Разрешённые Git/PR-действия выполнены после проверок, без обхода QA.
- Пользователю сообщены результат, проверки и оставшиеся ограничения.
