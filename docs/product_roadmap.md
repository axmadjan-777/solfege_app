## Как читать статусы

- **Реализовано в коде** — есть соответствующий путь в проверенной версии.
- **Проверено автоматически** — указан конкретный успешный тест/прогон.
- **Принято** — выполнен согласованный пользовательский сценарий и его ограничения.
- **Предложено / открытый PR** — ещё не часть подтверждённого `main`.

Наличие коммита, экрана или зелёного CI не переводит всю функцию в «принято».

## Рабочий процесс и инфраструктура

**OPS-01 выполнено 2026-11-04.** Для `main` включена branch protection:
изменения через PR, обязательный `verify` от GitHub Actions (app ID `15368`),
актуальная база перед merge, применение правил к администраторам, запрет
force-push и удаления ветки, закрытие обсуждений перед merge. Обязательное
число человеческих approvals — 0; независимый ИИ-ревью остаётся задачей QA-02.
Настройка подтверждена чтением GitHub API и списком обязательных checks PR #14.
После merge включено автоматическое удаление рабочей ветки
(`delete_branch_on_merge=true`); защита `main` сохранена.
[Настройки защиты](https://github.com/axmadjan-777/solfege_app/settings/branches).
Это настройка GitHub, её не включает checkout или запуск локального харнесса.

Документация и общий QA внедрены через
[PR #14](https://github.com/axmadjan-777/solfege_app/pull/14). Состояние слияния
фиксирует сам PR, результаты конкретного коммита —
[GitHub Actions](https://github.com/axmadjan-777/solfege_app/actions), а публикацию —
окружение `github-pages`. Эти статусы проверяются отдельно; наличие файлов
workflow не подтверждает успешный deploy.

проверяются в самих PR, публикация — в `github-pages`.

Двенадцать исходных рабочих веток старого цикла удалены; их точные HEAD
сохранены тегами `archive/2026-11-04/<исходная-ветка>`
в [репозитории](https://github.com/axmadjan-777/solfege_app/tags).
Ветки четырёх черновиков сохраняются до их доработки или отдельного решения.
Уборка веток — выполненная задача, а не шаг автоматического QA.
