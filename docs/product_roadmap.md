Это очередь решений и приёмки, не разрешение агенту выполнить всё подряд.
Обновлять при согласовании задачи, реализации, проверке, merge или новом
подтверждённом ограничении; для статуса указывать основание и дату проверки.

## Как читать статусы

- **Реализовано в коде** — есть соответствующий путь в проверенной версии.
- **Проверено автоматически** — указан конкретный успешный тест/прогон.
- **Принято** — выполнен согласованный пользовательский сценарий и его ограничения.
- **Предложено / открытый PR** — ещё не часть подтверждённого `main`.

Наличие коммита, экрана или зелёного CI не переводит всю функцию в «принято».

## Очередь задач по результатам аудита

Задачи ниже **предложены**, работа приложения по ним этим обновлением не выполняется.
Выбирать одну задачу или явно согласованный набор.

| ID / приоритет | Подтверждённая проблема или цель | Критерий приёмки |
|---|---|---|
| APP-01 / P0 | Оболочка не передаёт `isMastered` в теорию и практику; значение по умолчанию — `false` | Через реальную оболочку сохранённый `mastered` открывает зависимый урок/тренажёр; незавершённая предпосылка оставляет замок; повторное открытие сохраняет результат |
| APP-02 / P0 | Локальная книга прогресса использует общий ключ и `userId=local` | На одном устройстве аккаунт B не видит и не получает прогресс A; возврат к A восстанавливает его данные; для прежнего локального прогресса согласована и проверена миграция |
| APP-03 / P1 | Заявленный состав MVP и текущая карта разошлись: уровни 5–11 показаны шире списка 56 | Согласована граница релиза; для каждого включённого урока/стадии есть проверяемый маршрут; отложенные явно обозначены и не запускаются как принятые |
| APP-04 / P1 | Карта/переходы тренажёров используют стартовые сценарии; наличие генераторов не подтверждает доступность всех стадий | Проверены фактический вход, выбор стадии, задания по её параметрам, запись, повторное открытие; таблица покрытия связывает IDs каталога с проверками |
| QA-01 / P1 | Тесты отдельных экранов не подтверждают связность всего пути | Сценарий оболочка → урок → результат → открытие тренажёра → перезапуск проходит автоматически с фейками; ручная проверка браузера/звука отражена отдельно |
| OPS-01 / P1 | Защита main и обязательный CI при аудите отсутствовали | В GitHub действует правило успешного Verify перед merge; исключения и права прямой записи проверены. Это отдельная настройка GitHub |
| OPS-02 / P1 | SQL/RLS и живые auth/Gemini не проверяются локальным QA | Отдельный тестовый проект: применена схема, проверены права двух аккаунтов, email/reset и Edge Function; есть воспроизводимый отчёт без секретов |

APP-01 подтверждён [оболочкой](../lib/features/app/main_shell_screen.dart),

APP-02 — [подключением](../lib/features/practice/progress/practice_progress_binding.dart)

APP-03 — [фильтром уроков](../lib/features/theory/screens/theory_level_screen.dart).
APP-04 — [переходами](../lib/features/practice/screens/practice_followup.dart).
